# Design

Everything about how PlxNative looks and feels to the person on the sofa lives in this folder or
is pointed at from it. Start here if you are changing the user interface or the user experience —
a screen, a component, a colour, a string's tone, a menu, the player's controls — or if you want to
understand the design system before proposing a change.

Code is NOT here. The design system is implemented (and enforced) in Rust under `rust-modules/`;
this folder holds the decisions, the specifications, the artwork and the pictures, and the map
below says which file in the code carries each one. When prose here and the code disagree, the
code (and its tests and lint gates) wins and the prose is stale.

## The product, in one paragraph

A native media client for television screens, driven by a TV remote. Two builds share one
interface: the original LG webOS television client for Plex servers, and a Linux build that plays
video files from the machine's own disk (`docs/linux.md`). Both draw the same 1920×1080 canvas with
the same components; the Linux build swaps the Plex home for a folder library.

## The surface (constraints every design must respect)

- **One canvas: 1920×1080** (`rust-modules/ui/src/consts.rs`, `SCR_W`/`SCR_H`), scaled uniformly to
  the panel. No responsive layouts, no second viewport. Keep content inside the overscan-safe frame
  (`consts::SAFE`, `MARGIN_X`).
- **Ten-foot UI, remote first.** Input is a D-pad, OK, a long-press on OK ("hold"), Back and a few
  media keys. Focus is the primary state; hover is not a discovery mechanism. Every action must be
  reachable with arrows and OK.
- **Distance sets legibility.** Text sizes are a fixed scale; `CAPTION` 24 px is the floor for
  ordinary content.
- **Video plays behind the UI**, on its own plane on the TV. Panels over video need their own
  opaque or dimmed ground (see the glass and dim policy in the UI guide).

## Where the design system lives in code

The binding rules for UI code are [`rust-modules/ui/src/CLAUDE.md`](../rust-modules/ui/src/CLAUDE.md)
(the four rules: no raw colours, no raw text sizes, no hand-placed text, improve a component before
forking one; plus the settled product idioms). Screens follow
[`rust-modules/screens/src/CLAUDE.md`](../rust-modules/screens/src/CLAUDE.md).

| Concern | Where |
| --- | --- |
| Colour roles and palette | `rust-modules/ui/src/theme.rs` (roles over private primitives) |
| Type scale, spacing | `rust-modules/gfx/src/gfx/tokens.rs` (`size::*`, `space::*`), re-exported as `theme::size` |
| Canvas, margins, safe frame | `rust-modules/ui/src/consts.rs` |
| Text layout | `ui/src/label.rs` (one run), `ui/src/text_view.rs` (wrapped) |
| Components | `ui/src/widgets.rs` (buttons, marks, overlays, poster labels), `ui/src/cards/` (shelves, grids, card stacks), `ui/src/table.rs` + `ui/src/form.rs` (menus and settings), `ui/src/popover.rs` (anchored panels), `ui/src/hold_hint.rs` |
| Icons | `ui/src/icons.rs` over `design/icons/*.svg` |
| Player HUD and its panels | `rust-modules/appkit/src/` (`player_hud.rs`, `track_menu.rs`, `more_menu.rs`, ...) |
| Screens | `rust-modules/screens/src/` (`home/`, `library/`, `detail/`, `search/`, `player/`, `local.rs` for the Linux library, `item_menu.rs`) |
| Words on screen | `locales/{en,es,be}/*.json` (every string the app draws, with a description for translators); see [`specs/localization.md`](specs/localization.md) |

## Product idioms already decided

The UI guide records these as settled owner verdicts; propose changes knowingly, not by accident:

- Menus are **popovers anchored beside their trigger**, never full-screen sheets
  ([`screenshots/linux/03-item-menu.jpg`](screenshots/linux/03-item-menu.jpg)).
- A menu never opens with focus on a destructive row.
- Card marks have fixed meanings: an amber resume **bar** is "how far in", a **✓** is "finished",
  an amber **▶** means "this press plays" ([`screenshots/linux/02-films.jpg`](screenshots/linux/02-films.jpg)).
- The player HUD carries a state glyph, not a transport button row; transport is the remote's job
  ([`screenshots/linux/05-player.jpg`](screenshots/linux/05-player.jpg)).
- Failure read-outs are calm (secondary ink, never red); refusals on the Linux build arrive as a
  toast at the bottom of the screen.
- Clickable text marks are ALL CAPS.

## Seeing a change

- **Desktop simulator** (macOS / Windows WSLg): the `ui-sim` skill (`.agents/skills/ui-sim/`) —
  layout, focus, navigation and screenshots against a mock Plex server; `make screenshots`
  regenerates `screenshots/`.
- **Linux build** (any Linux desktop): `LINUX_DEV=1 make linux`, then
  `PLXNATIVE_MEDIA_DIRS=design/demo-library/library PLXNATIVE_FULLSCREEN=0 dist/linux/plxnative/plxnative`.
  With `LINUX_DEV=1` the app reads remote keys written to the FIFO `plxnative-remote` in its runtime
  directory (`up down left right ok back`, `okdown`/`okup` for a hold, `shot` for a screenshot).
- **The television** decides anything about real pixels, LG's text rasterization, video-plane
  composition and frame rate: the `which-tier` skill says which tier can see which change.
